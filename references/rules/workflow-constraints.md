# 工作流约束规范

约束 AI 助手与开发者在本仓库中执行代码修改、Git 操作和运维动作时的行为边界。约束力分级见 [index.md](index.md)。

## 1. Git 分支约束

- 1.1 【强制】禁止直接在 `master` / `main` 分支上修改被 Git 跟踪的文件。执行任何修改前必须先确认当前分支（`git branch --show-current`）；若处于 `master` / `main`，必须先签出新分支，或提示用户手动切换分支后再执行。
- 1.2 【强制】新分支命名使用 `<type>/<short-description>` 格式，`type` 取值：`feat`、`fix`、`docs`、`refactor`、`chore`、`hotfix`。示例：`feat/shopee-booking-sync`、`docs/workflow-constraints`。
- 1.3 【强制】禁止对 `master` / `main` 执行 `git push --force`、`git reset --hard` 后强推、`git rebase` 后强推等改写远端历史的操作。
- 1.4 【推荐】功能分支保持短生命周期，合并回主干后及时删除。

## 2. Git 提交约束

- 2.1 【强制】未经用户明确要求，不得执行 `git commit` / `git push`；完成修改后停在工作区状态，由用户确认后再提交。
- 2.2 【强制】禁止使用 `git add .` / `git add -A` 盲目暂存；必须逐一列出与本次任务相关的文件。
- 2.3 【强制】禁止提交敏感信息：密钥、Token、数据库密码、生产环境连接串等。配置模板使用占位符，真实值放入被 `.gitignore` 忽略的本地文件。
- 2.4 【强制】禁止执行会丢弃用户未提交工作的操作（`git checkout -- .`、`git clean -fd`、`git stash drop` 等），除非用户明确要求。
- 2.5 【推荐】提交信息使用 Conventional Commits 格式：`<type>(<scope>): <subject>`，subject 使用中文或英文均可，但需描述"为什么改"而非仅"改了什么"。

## 3. 文件操作约束

- 3.1 【强制】删除或覆盖文件前必须先查看目标内容；若发现内容与预期不符，或该文件并非本次任务创建，必须先向用户说明再操作。
- 3.2 【强制】禁止修改 `.git/` 目录内部文件、他人正在编辑的工作区文件。
- 3.3 【推荐】批量重命名、移动、删除操作先输出清单供用户确认，再执行。

## 4. 数据库与运维约束

- 4.1 【强制】禁止直接对生产数据库执行 DDL / DML；所有变更必须落为 `docs/sql/` 下的 SQL 脚本，由用户审核后手动执行。
- 4.2 【强制】需要用户手动操作的步骤（执行 SQL、修改配置、重启服务等），必须写入 `docs/manual.md`；每项必须含关联任务、前置条件、精确命令和参数、验证方式及回滚方式。新增待办使用头插法，放在未完成列表第一条，禁止追加到末尾。
- 4.3 【强制】禁止在未确认影响范围的情况下重启服务、清空队列、删除消费位点等改变系统运行状态的操作。

## 5. 文档同步约束

- 5.1 【强制】代码变更影响行为、接口、架构、部署或约束时，必须同步更新对应文档（`docs/agent-spec/`、`docs/architecture.md`、`docs/decisions/` 或 `docs/rules/`）；纯内部实现变化无需制造无意义的文档改动。
- 5.2 【强制】新增规范文件后必须更新 `docs/rules/index.md` 索引；新增文档目录后必须更新 `AGENTS.md` 索引。

## 6. 任务记录与 Handoff 约束

- 6.1 【强制】跨模块、接口/数据、安全或多个可验证 Agent 步骤的改动，必须在 `docs/tasks/active/` 创建或更新任务记录，写明 Agent 的目标、范围、计划、验证和风险。
- 6.2 【强制】任务计划中的步骤必须是 Agent 可执行且可验证的动作；每完成一步立即将 `[ ]` 改为 `[x]`，并更新执行记录、当前状态和下一步动作。禁止在任务记录中写入用户命令、控制台操作、人工待办或人工操作结果。
- 6.3 【强制】任务中断后，继续工作前必须先读取任务记录的 `Current State` 和 `Next Action`；范围变化时先更新记录。
- 6.4 【推荐】Agent 动作验证通过后，将任务移到 `completed/`，更新状态、时间和 `docs/tasks/index.md`。人工操作必须只写入 `docs/manual.md`，不得让已完成任务因等待用户操作而长期停留在 `active/`。

## 7. 本地协作文档忽略约束

- 7.1 【强制】使用 `index-docs` 生成的本次新建 `AGENTS.md`、`docs/` 文件和目录必须加入 `.gitignore`，不得执行 `git add` 将其纳入版本控制，以免污染其他成员的 Agent 定制。
- 7.2 【强制】修改 `.gitignore` 前必须查看已有规则、`git status --short` 和 `docs/` 内容；优先写入本次生成文件的精确路径。只有 `docs/` 完全由本次生成时，才允许忽略整个 `/docs/`。
- 7.3 【强制】禁止使用 `*.md`、`docs/` 等宽泛模式遮蔽已有文档；已有被 Git 跟踪的文件不自动取消跟踪，不得擅自执行 `git rm --cached`。
